This page documents how each Base Schema business group (BG) changes for Oman's e-invoicing requirements. Only fields that differ from the Base Schema are listed here — see the Base Schema reference for the full field set.

## BG-1. Invoice Information

**New Mandatory Fields:**
- `uuid` — A UUIDv4/UUIDv5-format universally unique identifier assigned to the invoice
- `issueTime` — The time the invoice was issued (e.g., `14:30:00`)
- `profileExecutionID` — Invoice transaction type with text label (e.g., "Tax Invoice")

**Changed Status (Conditional Mandatory → Optional):**
- `dueDate` — Invoice due date
- `buyerReference` — Buyer's internal reference identifier

**New Conditional Mandatory Fields:**
- Prepayment references (`originatorDocumentReference`) — required when paid amounts exist
- Profit margin fields — required when profit margin totals are provided
- Supporting document UUID — required for export invoices with specific VAT exemptions
- Tax exchange rate fields — required when invoice currency differs from OMR

**New Optional Fields:**
- `paymentTerms.paymentMeansID` — Payment instructions identifier
- `prepaidPayment` block — Prepayment tracking (ID, amount, date, type)
- `paymentTerms.installmentDueDate` — Instalment due dates

<Callout kind="info" collapsed="false">
  The schema introduces specialized references through `additionalDocumentReference[]` occurrences with fixed document type codes (e.g. "130" for invoiced objects, "PM_TOTAL" for profit margins) to manage syntax binding requirements.
</Callout>

## BG-3. Preceding Invoice Reference

| Field | JSON Path | Type | Code | Change from Base |
|---|---|---|---|---|
| Preceding Invoice reference | `billingReference[].additionalDocumentReference.id` | Identifier | IBT-025 | Mandatory → Conditional |
| UUID | `billingReference[].additionalDocumentReference.uuid` | Identifier | BTOM-031 | New Conditional |
| Issue date | `billingReference[].additionalDocumentReference.issueDate` | Date | IBT-026 | Optional → Conditional |
| Reason code | `billingReference[].additionalDocumentReference.documentStatusCode` | Code | BTOM-032 | New Conditional |

These fields become mandatory when the invoice type code is `381` (credit note), `383` (debit note), or `261` (corrective invoice), or when the transaction type is a profit margin invoice. The schema adds a UUID field and a reason code field not present in the base schema, requiring the UUID of the preceding (referenced) invoice being credited or debited.

## BG-7. Seller

**New Conditional Mandatory Fields:**
- Seller UUID (BTOM-004) — stored in `additionalAccountID`, required when buyer electronic address is `997770000099`
- Seller Identifier (textual code) (BTOM-015) — via `schemeName`, required for Special Zone supplies when seller country subdivision differs from `MO`
- Tax scheme code (SB-AUTO-24) — for seller tax registration, required when tax registration identifier provided
- Third Party Name / Third Party VATIN (BTOM-005 to BTOM-006) — for disclosed agent scenarios, required when invoice transaction type is Third-party Invoice

**Changed Status (Optional → Conditional Mandatory):**
- Scheme identifier (IBT-029-1)
- Tax scheme code (IBT-031-1)
- Seller tax registration identifier (IBT-032)

<Callout kind="info" collapsed="false">
  The Oman schema introduces comprehensive third-party and agent billing support with mandatory address components (street name, additional street name, city, postal code, address line 3, country code) and tax identification when invoice transaction type designates third-party invoicing.
</Callout>

## BG-10. Buyer

| Field | JSON Path | Type | ID | Change |
|---|---|---|---|---|
| Buyer identifier | `accountingCustomerParty.party.partyIdentification[].id.value` | Identifier | IBT-046 | Optional → Conditional Mandatory |
| Buyer Identifier (textual code) | `accountingCustomerParty.party.partyIdentification[].id.schemeName` | Code | BTOM-018 | New Conditional Mandatory |
| Buyer VAT identifier | `accountingCustomerParty.party.partyTaxScheme[].companyID` | Identifier | IBT-048 | Optional → Conditional Mandatory |
| Tax scheme code | `accountingCustomerParty.party.partyTaxScheme[].taxScheme.id` | Text | IBT-048-1 | Optional → Conditional Mandatory |

**Conditional requirements:**
- Buyer identifier (IBT-046) is required when: (1) Buyer VATIN absent AND invoice transaction type is "Full tax invoice" with third-party, summary, continuous supply, export, profit margin, or e-commerce classifications; or (2) Special Zone supplies with non-MO subdivision codes; or (3) Import transactions.
- Buyer Identifier textual code (BTOM-018) is newly mandatory for Special Zone supplies (non-MO regions) and import scenarios.
- Buyer VAT identifier (IBT-048) is required when buyer identifier is unavailable under the specified transaction types, or for self-billed invoices, RCM service imports, profit margin self-invoices, and import of goods.

## BG-20. Document Level Allowances/Charges

**Allowances (IBG-20):**
- Charge Indicator (`chargeIndicator`) — Boolean, Optional → Conditional Mandatory when allowances provided
- Allowance Amount (IBT-092) — Number, amount without VAT, Mandatory → Conditional Mandatory
- Allowance Base Amount (IBT-093) — Number for percentage calculation, Conditional Mandatory when percentage supplied
- Allowance Percentage (IBT-094) — Number, Optional → Conditional Mandatory
- VAT Category Code (IBT-095) — Code identifier, upgraded to Conditional Mandatory
- VAT Exemption Reason Code (IBT-196) — New Conditional Mandatory when category is `E` or `Z`
- VAT Exemption Reason Text (IBT-197) — New Conditional Mandatory field for exemption explanation

**Charges (IBG-21):** mirrors the allowance structure — Charge Indicator, Charge Amount (IBT-099), Charge Base Amount (IBT-100), Charge Percentage (IBT-101), VAT Category Code (IBT-102), and new exemption reason fields (IBT-198, IBT-199).

**New Elements:** Currency code fields (SB-AUTO-64, SB-AUTO-65, SB-AUTO-70, SB-AUTO-71) added as Conditional Mandatory when monetary amounts are provided, requiring ISO 4217 alpha-3 codes matching invoice currency.

**Tax Scheme:** fixed value `VAT` required in all cases, upgraded to Conditional Mandatory.

## BG-22. Document Totals

**Cardinality Shifts:**
- Invoice total TAX amount: Optional → Mandatory
- Sum of allowances/charges: Optional → Conditional Mandatory (when parent groups exist)

**New Mandatory Fields** (currency codes):
- `taxTotal[].taxAmount.currencyID`
- `legalMonetaryTotal.lineExtensionAmount.currencyID`
- `legalMonetaryTotal.taxExclusiveAmount.currencyID`
- `legalMonetaryTotal.taxInclusiveAmount.currencyID`
- `legalMonetaryTotal.payableAmount.currencyID`

**New Conditional Mandatory Fields:**
- Invoice total VAT in tax accounting currency (when currency differs from OMR)
- Currency codes for allowances, charges, prepaid, and rounding amounts (when respective amounts provided)

**New Optional Field:** Tax inclusive pricing indicator (`taxIncludedIndicator`)

<Callout kind="info" collapsed="false">
  All currency codes must use ISO 4217 alpha-3 format and align with invoice currency or tax accounting currency codes where applicable.
</Callout>

## BG-27. Invoice Line Charges/Allowances

- Charge Indicator (`chargeIndicator`) — Boolean toggle distinguishing allowances (`false`) from charges (`true`)
- Amount fields (allowance/charge) require both a numeric value (without VAT) and a currency code in ISO 4217 format matching invoice currency
- Base Amount Currency (`baseAmount.currencyID`) — separate currency specification for percentage-based calculations

Several fields are marked New Conditional Mandatory: currency codes became explicit conditional requirements, syntax binding qualifiers are now mandatory technical fields, and amount fields transitioned from Optional to Conditional Mandatory when allowances/charges exist.
