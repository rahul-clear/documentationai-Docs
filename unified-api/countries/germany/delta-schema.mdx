---
title: Germany - Delta Schema
description: 'How Germany''s BIS Billing and XRechnung schemes differ from the ClearTax Base Schema'
---

Germany supports two e-invoicing schemes on top of the ClearTax Base Schema: **BIS Billing** and **XRechnung**. Each has its own set of field-level deltas, documented separately below.

## BIS Billing

### BG-001. Invoice Information

| Field | JSON Path | Type | BT ID | Description | Delta vs Base |
|---|---|---|---|---|---|
| Buyer reference | `buyerReference` | Alphanumeric | IBT-010 | An identifier assigned by the Buyer used for internal routing purposes | Conditional Mandatory → Optional |
| Purchase order reference | `orderReference.id` | Alphanumeric | IBT-013 | Reference number of the Purchase Order or Purchase order number | Conditional Mandatory → Mandatory |
| Value added tax point date | `taxPointDate` | Date | IBT-007 | Date when tax accountability occurs for seller/buyer, or payment receipt date for advance invoices | Optional → Conditional Mandatory |
| Invoiced Object Identifier Scheme Identifier | `additionalDocumentReference.id.schemeID` | String | IBT-018-1 | Scheme identifier chosen from the UNTDID 1153 code list | Optional → Conditional Mandatory |

<Callout kind="info" collapsed="false">
  Tax point date becomes conditionally mandatory when the invoice date differs from the supply/delivery date. Scheme identifier becomes conditionally mandatory when an invoiced object identifier is supplied.
</Callout>

### BG-003. Preceding Invoice Reference

| Field | JSON Path | Type | BT ID | Description | Delta vs Base |
|---|---|---|---|---|---|
| Preceding invoice number | `billingReference.invoiceDocumentReference.id` | Alphanumeric | IBT-025 | Identifies the original invoice being adjusted by a Credit Note, Debit Note, or Corrective invoice | Mandatory → Conditional Mandatory |
| Preceding invoice issue date | `billingReference.invoiceDocumentReference.issueDate` | Date | IBT-026 | The date the original invoice was issued | Optional → Conditional Mandatory |

Both fields become mandatory when issuing Credit Notes, Debit Notes, or Corrective invoices, to ensure accurate reconciliation and auditability.

### BG-004. Invoice Note

| Field | JSON Path | Type | BT ID | Description | Delta vs Base |
|---|---|---|---|---|---|
| Invoice note | `note.value` | String | IBT-022 | Unstructured note relevant to the invoice or document | Optional → Conditional Mandatory |

Becomes conditionally mandatory for property-related services (construction, repair, gardening) supplied to private customers, where the invoice must include a note about a 2-year retention obligation under German tax law (§ 14b Abs. 1 Satz 5 UStG).

### BG-018. Credit Transfer

| Field | JSON Path | Type | BT ID | Description | Delta vs Base |
|---|---|---|---|---|---|
| Payment account identifier | `paymentMeans.payeeFinancialAccount.id.value` | Alphanumeric | IBT-084 | IBAN used to specify the seller's bank account | Mandatory → Conditional Mandatory |

### BG-019. Payment Card Information

| Field | JSON Path | Type | BT ID | Description | Delta vs Base |
|---|---|---|---|---|---|
| Payment card primary account number | `paymentMeans.cardAccount.primaryAccountNumberID` | String | IBT-087 | PAN of the payment card; only the last 4-6 digits should be shown | Mandatory → Conditional Mandatory |

Becomes mandatory when the payment method is a payment card (credit, debit, corporate) and card information appears under Payment Means (BT-81 codes 48, 54, 55). When these codes apply, IBT-084, IBT-085, IBT-086, IBT-089, IBT-090, and IBT-091 must not be provided.

### BG-022. Document Totals

| Field | JSON Path | Type | BT ID | Delta vs Base |
|---|---|---|---|---|
| Invoice total VAT amount | `taxTotal.taxAmount.value` | Numeric | IBT-110 | Optional → Mandatory |

<Callout kind="info" collapsed="false">
  This is the VAT total expressed in the accounting currency (EUR). Required in all cases, regardless of whether the invoice currency is EUR or foreign (USD, GBP, INR, etc.). When the invoice currency is EUR, this equals the invoice total VAT amount; for foreign currencies, it equals the invoice total VAT amount × exchange rate.
</Callout>

### BG-010. Buyer

- **Buyer legal registration identifier scheme** (`schemeID`): Optional → Conditional Mandatory — required when a legal registration number is declared.
- **Buyer VAT identifier** (`companyID`): Optional → Conditional Mandatory — required for intra-community supply/reverse charge; must NOT be provided when VAT category is "Not subject to VAT".

- **Buyer tax scheme code** (`taxScheme.id.value`): Optional → Mandatory — fixed value `VAT`.

### BG-030. Line VAT Information

| Field | JSON Path | Type | BT ID | Delta vs Base |
|---|---|---|---|---|
| Invoiced item VAT category code | `invoiceLine.item.classifiedTaxCategory.id` | Code | IBT-151 | Optional → Conditional Mandatory |

Must use UNTDID 5305 codes: S (Standard), Z (Zero-rated), E (Exempt), AE (VAT Reverse Charge), K (EEA intra-community exemption), G (Free export), O (Outside tax scope), L (Canary Islands indirect tax), M (Ceuta/Melilla production tax). Every SubInvoiceLine must specify a VAT category code for KoSIT-compliant VAT breakdown grouping.

**New structural groups** introduced for XRechnung compliance:

- **SUB INVOICE LINE** (BG-DEX-01) — individual invoice items
- **SUB INVOICE LINE ITEM INFORMATION** (BG-DEX-02) — goods/services details
- **SUB INVOICE LINE ALLOWANCES** (BG-DEX-03) — item discounts
- **SUB INVOICE LINE CHARGES** (BG-DEX-04) — surcharges/costs
- **SUB INVOICE LINE PERIOD** (BG-DEX-05) — billing period specifics
- **SUB INVOICE LINE VAT INFORMATION** (BG-DEX-06) — sales tax details
