Sales Documents is where you manage all outbound e-invoices you issue - tax invoices, credit notes, debit notes, self-billed invoices, and other document types your customers receive from you. It covers three broad activities:

1. Creating invoices (manually, via bulk import, or via API/ERP integration)
2. Monitoring their journey through the Peppol network and the OTA
3. Acting on individual or multiple documents (sending, resending, downloading, printing, emailing, deleting)

## Getting to Sales Documents

From the e-Invoicing dashboard, either click the Sales documents tile in the main area, or click the Sales Documents icon in the left sidebar. Both land you on the Sales Documents list view.

## The Sales Documents list view

The list view has four zones from top to bottom: status summary tiles, actions bar, active filter chips, and the document table.

There are also subtabs separate for B2B and B2C invoices.

### Status summary tiles (top)

Seven tiles at the top show the count of documents in each state, scoped to your current filter selection:

| Tile                      | Meaning                                                                                                                                                                           |
|-------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Total                         | All documents matching current filters                                                                                                                                                |
| Pending                       | Awaiting submission - queued, retrying, or in manual review                                                                                                                           |
| Failed                        | Submission or validation failed; needs remediation                                                                                                                                    |
| Submitted to exchange network | Handed off to the Peppol network                                                                                                                                                      |
| Delivered to buyer network    | Reached the buyer's Access Point (C3)                                                                                                                                                 |
| Delivered to buyer            | Reached the buyer's ERP or system (C4)                                                                                                                                                |
| Received                      | Applies to self-billed invoices only - indicates a self-billed invoice raised on your behalf by a buyer has been received into your Sales Documents. Zero for typical outbound flows. |

Clicking a tile filters the table to that status.

### Actions bar

On the left of the actions bar:

- **Filter** button - opens the filter panel (see 3.4)

On the right:

- **Selected Rows: N** - counter of rows you've ticked in the table
- **Send** button - appears active only when one or more rows are selected. Triggers submission of the selected documents to the Peppol network.
- **Actions** dropdown - bulk operations on selected rows (see 3.5)

### Active filter chips

Any filter you've applied appears as a chip below the actions bar, showing the field name and the value. Each chip has an × to clear it individually, and a Clear All link removes every applied filter at once.

### Document table

Each row is one document. Default columns:

| Column                  | What it shows                                                                       |
|-----------------------------|-----------------------------------------------------------------------------------------|
| Checkbox                    | Select the row for bulk actions                                                         |
| Document Number             | Your invoice number (clickable - opens the detail view)                                 |
| Document Status             | ClearTax's view of where the document is                                                |
| Government Reporting Status | OTA's view of the reporting outcome (Not Submitted / Processing / Accepted / Withdrawn) |
| Document Date               | Invoice issue date                                                                      |
| Document Type               | Commercial invoice, Credit note, Self-Billed Invoice, etc.                              |
| Customer Name               | Buyer's legal name                                                                      |
| Customer VAT                | Buyer's Tax Registration Number                                                         |
| Total Document Amount       | Gross amount including tax                                                              |
| Total VAT Amount            | VAT portion                                                                             |

Columns can be shown, hidden, and reordered - see 3.5 (Actions → Show/Hide Reorder Column).

### Applying and clearing filters

At the bottom of the panel:

- **Apply** - applies your selections. The table refreshes and each active filter appears as a chip above the table.
- **Clear All** - resets every filter in the panel back to unselected.
- **×** (top-right of panel) - closes the panel without applying changes.

Individual filter groups have their own Clear link to reset only that group.

### Send

The Send button (blue, next to Actions) submits selected documents to the Peppol network for delivery to the buyer's Access Point.

Send is only available for documents in **Pending** or **Failed state.** For documents that have already been submitted successfully - Submitted to exchange network, Delivered to buyer network, Delivered to buyer - Send is not offered, since the network handles onward delivery from that point.

Two places to trigger Send:

- **Bulk:** from the list view, tick one or more rows and click Send in the actions bar.
- **Single:** from a document's detail view, click Send Document in the header (see 3.7).

### Field-level view

Each section renders as a form with fields laid out in a four-column grid. In read mode, fields display saved values as read-only. Mandatory fields are marked with a red asterisk (\*).

## The document detail view - header states

The detail view header changes based on the document's state:

**Successfully delivered document** (Delivered to buyer + Accepted) - only Edit is shown. Send Document is hidden - the network has already completed delivery.

**Failed document requiring action** (Failed + Not Submitted or Withdrawn) - both Send Document and Edit are shown, along with an "Invoice exchange error/warnings" banner at the top of the content area.

### Edit mode

Click Edit in the detail view header to switch fields from read-only to editable.

<Image src="https://raw.githubusercontent.com/rahul-clear/documentationai-Docs/main/images/countries/oman/product-guide/sales-documents/detail-view-in-edit-mode-with.png" width="2048" height="1081" alt="Detail view in edit mode with Save button" />

What changes when you enter Edit mode:

- The Edit button is replaced by a blue Save button in the top-right.
- Free-text fields switch from grey read-only boxes to white input boxes with "Enter a value" placeholders.
- Enum fields (Yes/No flags, currency codes) become dropdowns with "SELECT AN OPTION" placeholders and a chevron indicator.
- Date fields show a calendar icon; you can pick a date or type it in.
- Fields with a value have a small × to clear the value inline.
- A few fields remain non-editable even in Edit mode - for example, Unique Identifier Number on a saved invoice (system-generated and immutable once assigned).
- The "Invoice exchange error/warnings" banner remains visible so you can see which fields need fixing while you edit.

Mandatory fields keep their red asterisk (\*) in Edit mode. Clicking Save validates the document; if all mandatory fields are populated and business rules pass, the changes are persisted and the document typically moves to Pending for re-submission (use Send Document to push it back to the network).

## Understanding statuses

Every outbound document carries two independent status values throughout its lifecycle.

### Document Status (ClearTax → Peppol → Buyer)

| Status                    | What has happened                                           | Typical next state                                          |
|-------------------------------|-----------------------------------------------------------------|-----------------------------------------------------------------|
| Pending                       | Document is in ClearTax, awaiting submission                    | Submitted to exchange network (on success) or Failed (on error) |
| Failed                        | Submission or validation failed                                 | Fix and resend → Pending                                        |
| Submitted to exchange network | Handed off to Peppol (C2 → C3 in flight)                        | Delivered to buyer network                                      |
| Delivered to buyer network    | Reached the buyer's Access Point (C3)                           | Delivered to buyer                                              |
| Delivered to buyer            | Reached the buyer's ERP or system (C4) - terminal success state | (none)                                                          |

### Government Reporting Status (ClearTax → OTA)

| Status    | What has happened                                |
|---------------|------------------------------------------------------|
| Not Submitted | Reporting to the OTA has not yet been attempted      |
| Processing    | Report has been submitted; OTA is validating         |
| Accepted      | OTA has accepted the report - terminal success state |
| Withdrawn     | The document has been withdrawn from the OTA record  |

### What "healthy" looks like

For a successfully issued invoice, the terminal state is:

- **Document Status:** Delivered to buyer
- **Government Reporting Status:** Accepted

Anything else - especially Failed on Document Status or Withdrawn on Government Reporting Status - needs attention.

## Troubleshooting

When a document fails validation or submission, ClearTax surfaces the errors in two places:

1. On the list view - the row shows Failed under Document Status and (usually) Not Submitted or Withdrawn under Government Reporting Status.
2. Inside the document's detail view - a red "Invoice exchange error/warnings" banner appears above the Invoice Details section.

### Reading the error banner

Click View More on the banner to expand the full error list; click View Less to collapse it back to the summary.

Errors are labelled "Errors – Fix to continue" (red chip) - meaning submission is blocked until the underlying issue is corrected. Each error is a numbered line in the format:

&lt;Source&gt; : \[&lt;rule-code&gt;\] – &lt;message referencing Fawtara element IDs&gt;

Example:

1\. GOVT : \[fbr-126-om\] – In Price Details (IBG-29), Item price base quantity (IBT-149) and Item Gross Price (IBT-148) MUST be there.

Reading this error:

| Part                       | Meaning                                                                                                                                                                                   |
|--------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| GOVT                           | The error originates from the government-side (OTA / Fawtara) validation layer, not from ClearTax's pre-flight checks                                                                         |
| \[fbr-126-om\]                 | The specific Fawtara schematron business rule that failed. Every business rule in Fawtara has a stable identifier prefixed "fbr-" (invoice business rule) and suffixed "-om" (Oman-specific). |
| Message body                   | Plain-English description of what's wrong                                                                                                                                                     |
| (IBG-29), (IBT-148), (IBT-149) | References to specific elements in the Fawtara data model. IBG- prefixes are business groups; IBT- prefixes are business terms (individual fields).                                           |

### Fixing the sample error

For the fbr-126-om example above:

- **What went wrong:** For every line item in the invoice, the Price Details section (IBG-29) must include both an Item Price Base Quantity (IBT-149) and an Item Gross Price (IBT-148). One or both are missing.
- **Where to fix:** In the detail view, jump to the Line items section using the left navigation. For each line item, populate both fields.
- **Next steps:** Click Save. Once validation passes, click Send Document to resubmit.

### Where to look up rule codes

Fawtara rule codes (fbr-\*-om) are defined by the OTA / OpenPeppol Fawtara specification. Each code has a canonical description in the specification. When a rule is unfamiliar, cross-reference the code against the Fawtara rule catalogue.
